# 设计取舍

## 插件管理，节点执行

主站插件负责节点注册、配置、用户权限、媒体版本与导出凭证；节点负责代理、缓存与分发。配置集中在 Jellyfin 后台，减少分别维护节点管理页面和权限模型的工作。节点主动同步配置，因此新配置与撤销存在同步延迟。

![插件中的节点配置入口](images/node-settings.png)

## 按需缓存原文件

原文件按块缓存，Range 请求只填充缺失块，并合并相同块的并发回源。容量按节点限制，使用 LRU 淘汰；缓存键包含主站命名空间、路径、大小与修改时间。这减少首次请求的等待和额外流量，但文件在大小与修改时间均不变时被原地替换，无法仅凭这些元数据识别。[缓存身份](cache-identity.md)

普通播放转码只转发；分享点播使用固定的媒体版本、轨道和输出参数，独立缓存 HLS 分片。两者的会话与授权边界不同，因此不共享任意转码请求的缓存。

## 在主站转码

主站已有媒体、字幕和转码能力，节点无需媒体挂载或 GPU。分享可以烘焙字幕、统一输出格式，但首次生成仍受主站性能、网络和编码器能力限制。输出参考 [Jellyfin VRC Relay](https://github.com/Tokiichika/jellyfin-vrc-relay) 的 HLS / MPEG-TS 方案，未增加播放器专用接口。[点播输出](vod-output.md)

## 媒体范围授权

链接凭证绑定媒体、版本、节点、操作和有效期，不复用用户登录 token。插件在创建时检查权限；普通账号播放仍由主站判权。公开链接适合转发，但持有者在有效期内可以访问该授权资源。

![已生成链接及撤销入口](images/exports.png)

完整缓存的导出允许离线读取，从而提高主站故障时的可用性；代价是离线节点无法立即接收撤销与源文件变化。缺失块不伪装为完整文件，仍需主站在线。[导出链接](exported-links.md)

## 同源网页适配

插件通过启动中间件加载同源脚本，不修改 Jellyfin Web 文件。媒体菜单依赖 Web 12.2 的 DOM 结构，减少部署步骤，但升级网页版本需要重新适配和测试。[网页机制依据](reference-evidence.md)

独立默认主题等插件不属于 Edge 的安装包或镜像。领域术语见[术语表](CONTEXT.md)，接口见[协议契约](protocol.md)。
